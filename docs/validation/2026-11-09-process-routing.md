# Linux TUN: точные executable-правила, 9 ноября 2026

## Стенд

`tools/engine_apps.py` переиспользует изолированный namespace и echo-сервисы
из [TCP/UDP-стенда](2026-11-09-tun-traffic.md). Ядра и SHA-256 те же:
Xray 26.10.31 и sing-box 1.14.4, digest официальных архивов проверен до запуска.

В task-каталоге создаются две отдельные копии Python executable с одинаковым
basename `probe-python` в подкаталогах a и b. Клиенты запускаются отдельными
процессами; каждый отчёт подтверждает фактический `/proc/self/exe`.
Постоянных PID-правил нет, очередная проба получает новый процесс.

Синтетическая конфигурация разрешает только точный executable + тестовый CIDR:
Xray использует `process`, sing-box — `process_path`. Совпадение ведёт в direct
outbound с redirect на localhost echo соответствующего семейства. Остальное
блокируется. Затем ядро перезапускается с перестановкой разрешённого пути.

Проверки клиента требуют точный случайный echo-ответ для разрешённого пути
и известную сетевую ошибку для запрещённого; внутренняя ошибка клиента не
считается успешной блокировкой. Проверяются маршрут через TUN и RX/TX для
положительной пробы, TX для заблокированной. После завершения ядра остаётся
только lo; временные конфиги и копии executable удаляются.

## Полученный результат

Для обоих ядер прошли TCP/UDP по IPv4/IPv6 с a разрешённым/b заблокированным,
затем с b разрешённым/a заблокированным. Итого 16 успешных echo-проб и
16 заблокированных потоков. Одинаковый basename не смешал разные полные пути.

Наличие только полей в конфиге не использовалось как evidence. Успешный echo
невозможен при полном отсутствии attribution, поскольку fallback блокирует.
Игнорирование process-условия также обнаруживается: второй executable получит
echo и стенд завершится ошибкой.

## Границы доказательства

Это часть G-APP, а не закрытие полного gate. Ядро и клиенты работают в одном
user/network namespace с одним отображённым UID. Пробы последовательные.
Не проверены одновременные потоки разных приложений, раздельные proxy/DIRECT,
дочерние процессы браузеров, разные UID, systemd hardening, PID reuse,
AppImage/Flatpak/Wine и процессные DNS-политики. Стоимость attribution не измерена.

Python-копии проверяют различение executable, но не доказывают охват приложения
по desktop entry и не являются каталогом программ продукта. Системные службы
и другие пользовательские процессы не читаются нашим кодом; нативный lookup
выполняет выбранное ядро. Поддержка на обычном host с минимальными capabilities
требует отдельного запуска и не выводится из наличия прав внутри user namespace.

Исходники/контракты:
[Xray ProcessNameMatcher](https://github.com/XTLS/Xray-core/blob/v26.10.31/app/router/condition.go),
[sing-box process_path](https://sing-box.sagernet.org/configuration/route/rule/#process_path).
