## Метод и фактические gates

В каждом повторе отдельная VM и fresh GUI PID, normal Main.qml/production
backend/bridge, обычный HostConfig и real private Secret Service из fixture
PR147. Guest ELF hash совпал с retained ELF, bus owner PID совпал с собственным
foreground gnome-keyring; по одному item. Ephemeral-key bypass не использован.
Fresh storage: профили/подписки/правила не импортировались, Connect/Probe-команд
нет, proxy engine не установлен в fixture data directory. Это idle baseline,
а не P-04 normal/stress workload.

Перед фазами **в том же GUI процессе** выполняется VisibleFrameCanary через
закрытый control FD. Фактические counters: `6→7`, `5→6`, `6→7`. Далее штатный
Hide, 60 с setup вне измерения и fresh Snapshot baseline. Каждая фаза длится
не менее 900 с; static-open тоже имеет 60 с setup после Open. В каждой фазе
181 внешний sample с шагом 5 с. Smoke replay timer 25 мс и deadline 45 с не
используются; observer не имеет polling timer/per-frame I/O.

Все шесть фаз сохранили правильную конечную visibility и неизменный
visibility_events относительно baseline (`1→1` hidden, `2→2` open).
Redraw измеряется **только QQuickWindow::frameSwapped Main.qml**, не paint-events
tint2/композитора. У всех шести фаз delta `0`. Короткие actual GUI controls
отвергли отсутствие нового кадра и реальные Hide/Open transitions;
[proof](../evidence/p01-idle-20261114/short-controls.json). Broken canary не
принимается отчётом как COMPLETE; это дополнительно проверено pure test.
[Phase proofs](../evidence/p01-idle-20261114/phase-proofs.json).

одновременных samples, не сумма RSS.

Разброс CPU hidden: `0.01556–0.01667%`, static-open: `0.01556–0.02000%`.
Начальный hidden budget `≤0.2%` выдержан в каждом повторе в этом fixture.
`SC_CLK_TCK=100`: один tick — 0.01 с, около 0.00111% CPU за 900 с; `0.00 с`
не означает доказанный абсолютный ноль. Относительную регрессию 10% при таких
малых CPU times без закреплённого baseline не объявляем.

Следующие диапазоны — разброс **медиан отдельных повторов**, память в KiB;
wakeups — фактическое число за одну 900-секундную фазу.

| --- | ---: | ---: | ---: |

Wakeup source: `/proc/PID/task/TID/sched`, `nr_wakeups`, guest
`kernel.sched_schedstats=1`; identities `TID:start_ticks` и counters сохранены.
GUI/tray thread sets стабильны на всех samples. Это scheduler wakeups, не
context switches и не атрибуция причин timer wakeups. Context switches
сохранены лишь как proxy. Причины отдельных bursts и пробуждений tint2 не
атрибутированы; универсальный gate отсутствия любых собственных таймеров не
подменяется этими числами. Overhead schedstats, observer и внешнего sampler
включён; отдельный default-binary overhead baseline не измерялся.

## Инфраструктура и условия

Bus, keyring, Xvfb и Openbox учтены отдельными строками в
[полной summary](../evidence/p01-idle-20261114/summary.json), а не скрыты в GUI.
Включая эти четыре процесса, суммарная median PSS шести guest процессов:
hidden `148634–149049 KiB`, open `148876–149278 KiB`; CPU всей этой группы —
hidden `0.01556–0.01667%`, open `0.01667–0.02111%`. Host QEMU, guest kernel и
остальные OS processes отдельно CPU/PSS не измерены: это не footprint всей VM
или физического устройства. Бюджет 64 MiB controller/helper без GUI при normal
нагрузке к этому объединённому GUI process не применяется.

Guest во всех трёх повторах: Arch kernel `7.2.11-arch1-1`, Qt base `6.12.0-5`,
Qt declarative `6.12.0-4`, gnome-keyring `1:51.1-1`, tint2 `17.0.2-7`, Xvfb
`21.1.26-1`. Host: CachyOS kernel `7.2.9-1-cachyos`, Qt `6.11.2`, Mesa
`26.2.4`, GCC `16.2.1`; retained ELF собран Rust 1.97.0, release/locked,
`--features gui,test-support`, jobs=1 через общий max-two Rust slot wrapper и
BSD shared flock собственного transient root.

[Host context](../evidence/p01-idle-20261114/host-context-summary.json): governor
`powersave`; AC0 online=1 на всех samples; load1 по повторам `0.27–3.65`,
`0.08–1.89`, `0.29–2.75`. Доступный `x86_pkg_temp`: `42–93°C` по всей кампании;
сырые показания остальных thermal zones сохранены, включая constant 0.05°C
SEN* — они не интерпретируются как CPU temperature. Host не был выделенным
тихим стендом, другие writer builds могли влиять на load. Battery-vs-AC,
physical Intel Arc GPU, full energy и physical Plasma не сравнивались.

## Reap, артефакты и границы

Все три GUI завершились штатным Quit, returncode=0 и wait/reap; audit завершён,
VM wrappers завершены, остаточных VM roots/старых supervisor/controller/audit
PID нет. Cleanup подтверждён фактическим завершением, не суммой таймаутов:
[terminal event](../evidence/p01-idle-20261114/terminal-event.json). OS reap
не имеет строгой гарантии по сумме 335 с; при живой VM результат должен быть
BLOCKED с handle/root, а не cleanup PASS. В этой кампании такого blocker нет.
Собственный Cargo target ранее очищен (`8078 files / 1.3 GiB`); retained ELF
и evidence находятся вне TTL.

Новых 16-probe runtimes, worker bootstrap, syscall/cross-UID экспериментов не
выполнялось. Во всех 1086 samples дочерних GUI processes нет; inventory с шагом
5 с не является exec/socket witness для краткоживущих событий между samples.
Не заявляем полную трассировку отсутствия transient exec. P-02, 100 циклов P-03,
8h energy, Android и P-07 log consumer/model apply этим proof не закрываются.

**Traffic stats-positive-canary N/A** только для frozen production source:

statistics consumer. Поля `ui_stats_delivery`/`statistics_poll` — `null`, not
measured, не измеренный ноль. Появление production statistics инвалидирует эту
узкую N/A связь. Она не относится к per-row log UI work P-07.
