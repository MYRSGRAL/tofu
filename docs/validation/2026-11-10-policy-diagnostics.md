# Диагностика пользовательских правил, 2026-11-10

База: `2be9a1bc8fcd553594e36e8a4c91614c15ba6251`.

Публичный API `yonik_domain::policy_diagnostics::diagnose(&Policy, Limits)`
возвращает `Result<Report, InputError>`. Изменений evaluator, backend и QML нет.
Диагностика не выполняет DNS, сетевых запросов или обращений к ОС.

Пример будущего UI:

```rust
use yonik_domain::{Policy, policy_diagnostics::{diagnose, Limits, WarningKind}};
fn предупреждения(policy: &Policy) {
    match diagnose(policy, Limits::default()) {
        Ok(report) => {
            for warning in report.warnings {
                let доказано = warning.kind == WarningKind::Shadowed;
                // Связать warning.rule_id с карточкой; earlier — источник старшего правила.
                // action/earlier_action позволяют отличить одинаковые и разные действия.
                let _ = (warning, доказано);
            }
            // При report.truncated показать неполноту проверки.
        }
        Err(error) => { let _ = error; /* Показать ошибку входной политики. */ }
    }
}
```

`Shadowed` доказывает включение условий младшего правила в одно старшее:
AND между source/domain/CIDR, OR внутри каждой группы, пустая группа универсальна.
Каждое младшее значение должно покрываться одним старшим значением; объединение
нескольких соседних CIDR в более широкую сеть не вычисляется. Exact executable
сравнивается как путь без нормализации, наследования или обращения к файловой системе.
Suffix включает корень и поддомены только по границе метки. Семейства CIDR различаются.
Одинаковое действие также предупреждается: младшее правило всё равно недостижимо.

`PotentialOverlap` означает совместимость либо неизвестность, а не доказанное
существование потока. В частности, разные CIDR могут совпасть на разных адресах
одного DNS-ответа. Соответствие домена CIDR статически неизвестно. Приватные
назначения всегда дают только потенциальное предупреждение: доступность VPN,
неоднозначность владельцев и DNS могут завершить вычисление раньше решения.
`Shadowed` относится к включению селекторов, не гарантирует успешный DNS или VPN.
Приватные сети/домены, затем LAN, затем user и preset обходятся в порядке политики.
Предупреждения выдаются для user и preset, с идентификатором младшего правила.
Приватные источники обозначаются группой RuleOrigin, без выдуманного rule ID.
Disabled не участвуют в предупреждениях. Все ID, включая disabled и preset,
должны быть ненулевыми и глобально уникальными; это контракт нового API.

Пределы: не более 512 записей суммарно, 32 значения в каждой группе, 4096 байт
на executable и 1 MiB executable суммарно. Некорректные пути (не абсолютные или
с управляющими символами), ID и превышение размера дают InputError целиком.
DomainPattern/Cidr уже типизированы и проверены конструкторами модели.
Limits может уменьшить 512 записей, 32768 сравнений пар и 256 предупреждений,
но не увеличить эти потолки. Report содержит comparisons, work_units, truncated.
Дополнительный потолок работы — 16777216 консервативных единиц сравнений:
на пару 1 + 2 × (число пар executable × 4096 + пар domain × 253 + пар CIDR × 128).
Стоимость учитывает оба прохода сравнения и ограниченную длину значений.
При остановке возвращается детерминированный префикс, truncated=true;
отсутствие предупреждения в неполном отчёте ничего не доказывает.

Алгоритм парный, сознательно ограничен жёстким бюджетом, списками и объёмом строк;
ID индексируются BTreeSet за O(n log n). Нет неограниченного O(n²).
В отчёт не копируются пути, домены и DNS-данные. Полнота статического анализа,
доказательство совместимости DNS/CIDR и совокупного затенения несколькими
правилами не заявляются. UI обязан сохранять различие двух WarningKind и
не использовать диагностику вместо evaluator или блокировки применения политики.
