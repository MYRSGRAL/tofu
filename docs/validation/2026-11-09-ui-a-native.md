# Нативный UI А: реализация и проверка

Выбранная компоновка А перенесена в существующий Qt Quick/CXX-Qt host. Это
рабочий интерфейс Rust backend: карточка выбранного/активного сервера,
центральная кнопка подключения/остановки, статус, отдельный picker и настройки.
Окончательный toolkit и системный TUN этим этапом не объявляются готовыми.

## Поведение

- Почти чёрная тема, лавандовый акцент, Onest для текста и Unbounded для заголовков.
  Шрифты и OFL-лицензии встроены в ресурсы. При отсутствии явного выбора Qt style
  используется Basic, чтобы оформление не зависело от desktop-темы.
- На главном экране остаются выбор сервера, подключение/отмена/остановка, статус
  и шестерёнка. Все параметры, подписки и диагностика находятся в настройках.
- Picker сохраняет поиск, избранное, выбор источника и страницы по 200 профилей.
  ListView виртуализирован; имена и адреса показываются как plain text.
- Доступность основной кнопки определяется `can_connect`/`can_stop`; подпись и
  доступное имя различают остановку, отмену подключения и повтор cleanup.
  Enter активирует основную кнопку, Escape возвращает на главный экран; открытые
  модальные окна сохраняют собственные правила закрытия.
- Подписки и результаты частичного импорта используют прежний backend/review.
  Закрытие формы очищает URL и снимает раскрытие. HTTPS URL тоже очищается после
  отправки. Секретные поля не добавлены в snapshot/tray/trace.
- Ядро, локальный порт, язык и HTTPS target действуют на текущий сеанс. Прототип
  предоставляет SOCKS5 для явно настроенных приложений. TUN, системный proxy,
  Fake-IP и применённый kill switch не изображаются работающими настройками.

## Воспроизводимая проверка

`tools/desktop_ui_smoke.py` управляет только собственным QQuickWindow. C++ driver
включается только с `--smoke-test`: ограниченный набор click/key/text/value/resize,
проверка свойств именованных контролов и PNG собственного окна. Произвольного JS,
внешнего ввода мыши или захвата рабочего стола нет. Обычный GUI не включает
проверочный таймер; рабочий backend остаётся событийным.

Сценарий из 43 действий проверяет пустое состояние, переход в настройки, порт,
RU/EN, очистку отменённой формы, добавление своей loopback-подписки, discard и
approval частичного импорта, поиск, избранное, выбор сервера, подключение по
Enter и понятную ошибку отсутствующего ядра. Затем проверяются три TCP-соединения
без payload, настройка/сброс HTTPS target, очистка секретного поля и Escape.
Отдельные отрицательные сценарии отклоняют неизвестный контрол и traversal в
имени capture. В trace остаётся только прежний whitelist metadata.

Проверены размеры 640×780 (100%), 520×640 (150%) и 1000×900 (200%). Собственные
PNG просмотрены: кириллица, literal HTML-like имя, compact layout, error, picker
и review. Это Qt offscreen/software scaling, не приёмка живого Wayland.

```sh
# CARGO_TARGET_DIR указывает на удерживаемый flock собственный build-каталог.
python tools/desktop_ui_smoke.py "$CARGO_TARGET_DIR/debug/tofu-desktop" --output /путь/к/новому/ui-a
python tools/desktop_ui_smoke.py "$CARGO_TARGET_DIR/debug/tofu-desktop" --output /путь/к/новому/ui-a-compact --width 520 --height 640 --scale 1.5
```

`tools/desktop_smoke.py --case all` прошёл 14 сценариев с Xray 26.10.31 и
sing-box 1.14.4. Connect/Stop теперь выполняются настоящим нажатием центральной
кнопки, а `Connected`/`Limited` проверяются и в backend, и в тексте GUI. Проверены
HTTP 204, неожиданный 200 и ожидаемый пользовательский 200, затем
Stop → Disconnected → closed. Ядра запускаются в собственном PID namespace;
сеть хоста не меняется. TCP-сценарии отдельно различают literal, resolved,
недоступный resolver и отказ соединения. Все URL и credentials вымышленные.

Четыре дополнительных `--case network` сценария обоих ядер подтвердили сброс
устаревшего результата в `Limited/network_changed`, в том числе при ещё идущей
HTTPS-проверке, и последующую остановку центральной кнопкой. Backend: 19 тестов
проходят, один отдельный namespace-тест остаётся ignored в обычном запуске.
GUI clippy с `-D warnings`, Rust fmt, Ruff 0.17.4 и 80 Python-тестов проходят.
GCC16/Qt6.11 по-прежнему дают vendor header warning QChar SFINAE.

Дополнительный `cargo test -p tofu-desktop --features gui` выявил ограничение
существующей раскладки bridge: библиотечные test targets не линкуют Rust FFI,
который объявлен в binary. Обычные backend tests проходят без `gui`, GUI
проверяется сборкой, clippy и запуском собственного окна. Перенос bridge между
library/binary не включён в визуальную переработку.

## Границы

Работоспособность loopback fixtures не доказывает доступность конкретного
провайдера или всех видов профилей. Полная QA на разблокированном Wayland,
clipboard/tray и энергозамеры Qt/GTK4/Slint остаются впереди. Пользователь
отложил длинный benchmark до доступной разблокированной сессии; это не блокирует
данный рабочий прототип А. Нет заявления о закрытии G-UI/G-POWER/G-LINUX/G-DNS.

Следующие этапы продукта: системный network host/helper и TUN; согласованный
DNS/Fake-IP контракт; редактор маршрутизации и реальная сетевая защита; постоянные
настройки, recovery и поставка. Основная реализация остаётся на Rust.
