## Незакрытый инвариант

A-04 в `docs/specs/validation-and-roadmap.md:98` требует «Приложение + домен/CIDR
+ порт». Расширенный редактор по `docs/specs/routing-and-tray.md`, раздел 4,
должен представлять протокол/порт. На данной базе порт не имеет представления
в production API:

- `crates/yonik-desktop/src/editor.rs:7`: `RuleInput` содержит executable,
  domains, destinations и platform_sources, но не порт; `deny_unknown_fields`
  запрещает добавить произвольное поле в этот DTO.
- `crates/yonik-desktop/qml/Main.qml:1004`: UI явно сообщает, что порты
  неподдержаны; `routingSaveRule` сериализует перечисленные группы без порта.
- `crates/yonik-domain/src/policy.rs:70`: `Conditions` не содержит порта;
  `Flow` в том же файле содержит executable и IP.
- `crates/yonik-domain/src/evaluation.rs:73`: `DestinationFlow` содержит
  executable и destination, без transport port.
- `crates/yonik-desktop/src/backend.rs:6114`: inline PolicyApply WireRule
  передаёт domain/domain_suffix/ip_cidr/executable_paths/platform_sources,
  без поля порта.

Контрпример: правило Block для `/usr/bin/browser` + `example.org` +
`192.0.2.0/24` + destination port 443, default Proxy. Потоки к одному адресу
на 443 и 8443 обязаны различаться по этому правилу. В текущие `Conditions` и
`DestinationFlow` это различие передать нельзя. Это структурная невозможность
выразить контракт, не измеренный сетевой результат. Вставка caller property,
raw JSON вне DTO или подмена authority не исправляют API и здесь не применялись.

Нужен согласованный root дизайн port condition и flow metadata, включая
валидацию, совместимость Draft/wire, семантику И/ИЛИ, сохранение скрытого поля
через оба редактора и native admission. Здесь такой дизайн не вводится и
production change не предлагается как уже разрешённый. Пока решения нет,
полная A-04 и через неё полная P07/P20 остаются частичными.

normal Host/private SecretService запуска: mixed executable/domain/CIDR draft
с disabled selector → production order control → Simple↔Advanced → production
Save/ACK → завершение → fresh process на том же private SS/DB → полное равенство

отдельно на activation boundary с сохранением existing policy. Save enabled
unsupported draft сам по себе разрешён storage-контрактом и не является Apply.
Нельзя требовать отказа Save вместо отказа активации.

Новый build или повтор P03 3×100/A08 ради отсутствующего port API не выполнялись.
N5/TUN/process-domain enforcement не запускались и не объявляются доступными;
offline Save не выдаётся за native Apply. Host preferences, keys и сеть не
затронуты. FR16/backend incoming работа не редактировалась.
