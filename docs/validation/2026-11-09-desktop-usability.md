# Удобство desktop и Remnawave JSON

## Поведение

- Окно 520×800, минимум 520×640; центральная кнопка А, палитра highpriority.cloud.
- Настройки разделены на подключение, подписки, диагностику, интерфейс и сведения.
  Создаётся только открытая панель; подробности находятся в подсказках `?`.
- Прокрутка панели ограничена содержимым, без пустого overscroll. Списки остаются
  виртуализированными. Декоративных idle-анимаций и нового polling нет.
- ОС выбирает loopback-порт, проверяются TCP и UDP. Если порт занят перед Connect,
  автоматический режим выбирает другой. Гонка после освобождения preflight-сокетов
  остаётся: ошибка bind приводит к существующему cleanup, скрытого retry нет.
- Добавление ссылки запускает загрузку. JSON/частичный импорт требует review.
  Ошибка загрузки сохраняет источник для повторной попытки, фильтры сбрасываются.
- Пользовательский launcher `cloud.highpriority.tofu.local` запускает бинарник
  напрямую без терминала и порта в аргументах. Иконка и desktop-file ID согласованы
  с Qt. Installer сохраняет чужие файлы и допускает повтор после частичного сбоя.

## Remnawave

В официальном [списке клиентов Remnawave](https://github.com/remnawave/backend/blob/main/src/modules/subscription-template/constants/extended-clients.ts)
JSON fallback распознаёт `/^Happ\//`. Строка `Happ` этому правилу не соответствует.
Загрузчик использует `Happ/1.0 tofu/<version>`; настройки провайдера могут изменить
результат по [Response Rules](https://docs.rw/learn-en/templates/).

На предоставленной приватной подписке проверен HTTP 200/application-json:
7 конфигураций, 10 VLESS, 4 Shadowsocks, 2 Hysteria и инфраструктурные outbounds.
URL, credentials и тело не сохранялись в диагностические файлы; обработка — в RAM.
Новый импортёр получает 14 профилей, Hysteria явно отклоняет. Восемь профилей
получают блокирующие флаги дополнительных параметров. В проверенном ответе
6 VLESS компилируются для Xray, 4 — для sing-box. Остальные комбинации отклоняются
по возможностям транспорта/параметров; доступность удалённых серверов этим не доказана.

Из Xray JSON object/array извлекаются VLESS и Shadowsocks через общий URI normalizer.
Исходный JSON сохраняется для review, но его routes/DNS/inbounds не исполняются.
Вложенные повторные ключи отвергаются, неизвестные параметры не теряются молча.
`tls.enableSessionResumption=false`, отключённый mux и пустые TCP-настройки
распознаются как значения по умолчанию; прочие варианты проходят строгие guards.
`grpc.authority`, REALITY `spiderX`, `xhttp.extra`, Shadowsocks `finalmask`/UoT
пока могут блокироваться отдельным compiler guard. CLI `tofu-compile` сохраняет
прежнее требование полного URI-импорта; GUI компилирует подтверждённый профиль.

## Проверки и ограничения

- Rust 1.85.1: workspace tests и clippy `--all-targets -- -D warnings`.
- 47 тестов импортёра; fetch header/identity проверяется локальным HTTP fixture.
- Backend integration: JSON → review → подтверждение → выбор → compile до engine lookup.
- 91 Python-тест, включая 11 installer-тестов, реальный `gio launch`, fault injection.
- 50 действий в настоящем Qt UI при 520×800/100% и 520×640/150%: автоматический
  импорт, отмена/подтверждение review без устаревшего сообщения, поиск/избранное,
  выбор сервера, клавиатура, TCP-серия, смена языка/панелей, сохранение HTTP-статуса
  и прокрутка в обе стороны. Отсутствующий control и traversal screenshot отвергаются.
- Шесть изолированных GUI/HTTPS-сценариев с закреплёнными Xray и sing-box:
  ожидаемый 204, неожиданный 200 (`Limited`), пользовательский ожидаемый 200;
  во всех случаях Stop → Disconnected → закрытие без оставленного ядра.

Сравнительные замеры Qt/GTK4/Slint, длительный Wayland idle/hidden benchmark и
полная приёмка на разных Linux DE остаются отдельными gates. Эти проверки не
подтверждают системный TUN, kill switch или перенаправление трафика всей системы.
