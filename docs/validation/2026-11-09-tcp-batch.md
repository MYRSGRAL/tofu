# Пакет из 10000 TCP-серий

Добавлен Linux library API `check_tcp_batch`: до 10000 уникальных opaque ID,
параллелизм 1…32, timeout каждой серии до 60 секунд, mpsc capacity ≤32.
Scheduler не создаёт runtime или task на каждую цель. Сумма активных и готовых
к доставке результатов ограничена parallelism; канал имеет отдельный предел.
Desktop массовая команда, история и UI прогресса пока не добавлены.

## Проверки

TDD RED stub: шесть тестов выявили отсутствие валидации, ID/result delivery,
отмены, backpressure и Drop. После реализации на Rust 1.85.1:

- 146 unit и 22 integration tests пакета tofu-linux прошли; обычный запуск
  оставляет шесть tests ignored, включая явную нагрузочную проверку ниже.
- Полный workspace Clippy всех targets с -D warnings, fmt и diff check чистые.
- Отдельный load test прошёл: 10000 серий, все IDs уникальны, 30000 EOF без
  payload через pool 16 собственных loopback listeners. Этот exact test добавлен
  отдельным шагом CI. Пользовательские подписки и публичные адреса не проверялись.
- Валидация выполняется до сетевого I/O: размер, duplicate ID, timeout,
  параллелизм, ёмкость канала. Пустой пакет допустим.
- Проверены отмена во время I/O/доставки, receiver closure при зависших probes,
  Drop внешнего future, частичная ошибка одной цели и ограниченность jobs.

## Review и исправление P2

Независимый review подтвердил ошибку первоначального варианта: await send в
полный канал прекращал polling остальных futures и мог добавлять ожидание UI
к TCP-времени или давать ложный timeout. Regression RED давал finished=0 вместо
трёх завершённых jobs до чтения потребителем. Исправленный select продолжает
active.next во время backpressure и держит bounded completed queue. Regression
GREEN подтверждает progress до drain без wall-clock ожиданий.

Повторный узкий review исправления не нашёл новых findings. Предел очереди
сохраняется, отмена/закрытие receiver имеют приоритет, ожидающие futures
уничтожаются при выходе. Реальные TCP-тайминги при медленном потребителе отдельно
не измерены: тест подтверждает продолжение polling, а не аппаратную точность.

## Ограничения

Результаты приходят в порядке завершения. Producer success означает доставку в
канал; потребитель ещё должен дочитать его. После отмены уже доставленные
элементы могут оставаться в очереди: controller обязан применять revision и
network generation guards. Batch API не доказывает DNS provenance или стабильность
сети. G-PROBE целиком и G-UI/G-POWER остаются открытыми. Числа времени выполнения
load test — диагностический вывод одного запуска, не benchmark энергопотребления
или гарантия скорости на реальных серверах.
