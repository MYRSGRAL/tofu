# FR16: явное сохранение страницы журнала

База: `82d5fe7397dcfef01f82c48d54660efa974c9987`.

Добавлена команда `logs_save`: строковые request_id, page_request_id и абсолютный
путь нового файла. Команда принимает только ID последней страницы backend,
готовой после logs_read. Содержимое файла из GUI не принимается. Новый read,
чужой backend read или уже завершённый save делают старый ID непригодным.
Экспорт отмечен scope=page и partial=true: это ограниченная страница, а не
полный журнал. Счётчики evicted/rejected/missed остаются явными.

Каждый компонент каталога открывается относительно закреплённого FD с
DIRECTORY/NOFOLLOW. Временный файл имеет случайное имя, CREATE/EXCL и mode 0600.
После write_all и sync_all публикация renameat_with(NOREPLACE) не заменяет
существующий файл или symlink. fsync каталога отделяет saved от
saved_durability_unknown. Пути и ошибки ОС в snapshot не возвращаются.

LogsView использует существующий dispatch entrypoint. Путь вводится явно,
запись начинается только кнопкой «Сохранить страницу». Matching save ACK
обрабатывается отдельно от принятой страницы; старые ACK игнорируются.
Clipboard при сохранении не меняется. Отказ очереди и generation-cancel
возвращают ACK новой команды без export.

Evidence находится в `local/evidence/fr16-save/` и не входит в git.
Первый запуск теста компилировался одновременно с реализацией и является только
GREEN. Отдельный ack-red.log получен временным исключением logs_save из
production matching ACK helper: тест наблюдает старый ID 1 вместо нового ID 2.
QtTest использует настоящий LogsView и clipboard Qt, но подставной dispatch;
это не доказательство переполнения очереди настоящего DesktopHost.

Открыты: actual GUI busy/loss, negative exit/cleanup через доверенный hook
владельца FR19, immutable session-id/generation в core событиях и их lifecycle
wiring. Текущий EventLog не содержит контекста сессии; data-and-contracts §5
его требует. Изменения HostConfig/session lifecycle не входят в ownership
этого среза. Physical Plasma/GPOWER также не проверены. Полный FR16 PASS не
заявляется.

Проверенные результаты этого среза: Rust 1.85.1 — 33 library-теста,
4 прежних dispatch_error-теста, новый save ACK тест и 3 backend logs-теста
под private D-Bus; clippy all-targets без warnings. QtTest 6.11.2 — оба
поведенческих теста и init/cleanup (6 PASS). Qt RED на базовом LogsView
падает при обращении к отсутствующему logsDestination. Python contract tests —
4 PASS; RU/EN checker — 239 inline-пар и 96 ключей. qmllint содержит прежние
предупреждения unqualified access в delegate.

Actual GUI/DesktopHost: `native-final/{xray,sing-box}/trace.jsonl` — по 52 шага,
closed=true. Положительный native-path использует production pinned Xray и
sing-box; synthetic loopback профиль, private D-Bus и ephemeral DB. Через GUI
введён путь собственного fixture, нажата кнопка сохранения, затем повторного
сохранения в существующий файл. Clipboard-canary сохранён, экспорт содержит
CleanupConfirmed, mode=0600. Экспорт первой сессии не заменён после второй
сессии. Binary: `local/artifacts/fr16-save/yonik-desktop`, SHA256
`7ec1756f0965d1c9deca4c60b70d0618beb3d6d63d58002f3e8e54a8434b74ec`.

Первый native-прогон остановился на ошибочном частичном сравнении объекта
snapshot в условии стенда; исправлены только условия теста, повторный прогон
прошёл на том же binary. Это не Physical Plasma/GPOWER acceptance.
