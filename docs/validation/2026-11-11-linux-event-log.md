# Ограниченный журнал Linux lifecycle

База: `db8226ef585b8251fe02ca3dbbe0f7ac759fc636`. Частичный FR-16/P11/P25.

`LocalSession::new()?.with_event_log(log.clone())` явно подключает producer.
Прежние конструкторы сохранены. Выделяйте отдельный `EventLog` на сессию:
ID относятся к журналу; межсессионная корреляция и generation пока не реализованы.

App фиксирует запросы Start/Stop, успешный spawn и подтверждённую очистку.
Engine фиксирует фактический OS exit status после reap процесса при release.
Это наблюдение процесса, а не текстовое сообщение ядра. PID, адреса,
конфигурация и stdout/stderr не сохраняются. Последние остаются `/dev/null`:
новых pipe, задач, каналов и фонового polling нет. Сохранение всего native
текста и его whitelist-классификация этим изменением не заявляются.
`reject_native` отклоняет неизвестные bytes целиком со счётчиком.

В кольце максимум 2000 записей фиксированного размера, значительно меньше
2 MiB. Producer использует try_lock и при конкуренции увеличивает rejected,
не задерживая Stop. Read просматривает максимум 2000 записей и возвращает
максимум 256; фильтры source/code применяются до выдачи. Cursor проходит
отфильтрованные записи; missed сообщает разрыв, evicted — суммарное вытеснение.
Экспорт страницы ограничен 256 событиями, содержит только enum-коды и числа.
Исчерпание ID не приводит к wrap, событие отклоняется со счётчиком.

Проверки и логи находятся в `local/validation/event-log/`:

- Мутационная RED-проверка без вставки в кольцо падает; исходная реализация GREEN.
- Проверены лимит, cursor, фильтры, конкуренция, исчерпание ID, secret/ANSI canary.
- Реальный процесс sleep завершается через LocalSession Stop, reap подтверждён
  отсутствием `/proc/PID`, проверен порядок App/Engine/App.
- Отдельные запуски теста на закреплённых Xray 26.10.31 и sing-box 1.14.4
  выполняют `version` из immutable snapshot и проверяют OS exit code 0.

GUI consumer отсутствует. Полный FR-16, native сообщения и Linux release
приёмка остаются открытыми; нагрузка GUI, idle CPU и вся native сессия
не считаются проверенными этими узкими тестами.

`cargo clippy -p yonik-linux --all-targets -- -D warnings` блокируется
существующим `collapsible_match` в `yonik-engine/src/lib.rs:165`.
`--no-deps` проверяет локальные targets отдельно; общий baseline не исправлялся.
