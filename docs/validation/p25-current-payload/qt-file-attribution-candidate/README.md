## Точные candidate options, без election

[primary-conditions.json](primary-conditions.json) задаёт два разных варианта
для **только этих 20 hash-bound files**:

1. **GPL-3.0-only** — буквальный OR operand каждого файла. Доступный primary:
   `8ceb4b9ee5adedde47b31e975c1d90c73ad27b6b165a1dcd80c7c545eb65b903`.
   Это прямой кандидат для GPL3 distribution; исполнение source/notice terms
   и выбор operand здесь не объявляются.
2. **LGPL-3.0-only** — также буквальный operand. Доступны LGPL3
   `da7eabb7bafdf7d3ae5e9f223aa5bdc1eece45ac569dc21b3b037520b4464768`
   и указанный GPL3. LGPL3 включает GPL3 с дополнительными permissions; §3
   допускает object code с header material под terms of choice. Если material
   выходит за перечисленные в §3 малые категории, требуются prominent library/use
   notice и оба license documents. GPL3 application — возможный контекст этих
   terms, а не доказательство выполнения всех условий. §4 для Combined Work —
   отдельная проверка; exemption для small macros/templates здесь не предполагается.

Bare `GPL-2.0-only` не предлагается как GPL3 conversion; commercial entitlement
не предполагается. Никакой OR operand не выбран. Primary document byte identity
не меняет его applicability на другой source/version.

В частности, тексты GPL3/LGPL3/Qt exception в **current 6.11.2 package** побайтно
равны текстам historical **6.12.0 inventory**. Поэтому тексты доступны без нового
скачивания. Это **не** равенство исходников Qt 6.11.2 и 6.12.0.

## Generated outputs и исключения

[generated-and-exception-candidates.json](generated-and-exception-candidates.json)
разделяет четыре семейства: Qt moc/rcc, QML-generated outputs, CXX/CXX-Qt и
собственные guards/resources. Actual final generated bytes пока не заявлены.

`Qt-GPL-exception-1.0`, SHA
`40678d338ce53cd93f8b22b281a2ecbcaa3ee65ce60b25ffb0c462b0530846b2`, доступен
как installed primary и в retained offer. **Exception 1** касается larger work,
содержащего output covered application, с двумя ограничениями: work не должен
быть otherwise derived/based on application и не должен сам генерировать output,
содержащий original/modified output этого application. **Exception 2** касается
application + independent plugins и содержит source-offer notice condition.
Это не blanket exception для любых Qt headers/templates.

Установка package с этим identifier не доказывает file-level coverage конкретного
moc/rcc/QML tool. Поэтому WITH не добавлен ни к headers, ни к outputs. Применимость
Exception 1 — конкретный кандидат после совпадения tool source/output declaration;
эта declaration должна войти в нижеописанный source capsule. При фактически
GPL3-permitted output также существует GPL3 route без предположения о blanket
exception; его carrier надо сопоставить с retained bytes.

Retained Rust metadata даёт CXX-Qt **0.10.0**, cxx **1.0.176**, cxx-gen **0.7.176**
с `MIT OR Apache-2.0`. Все **20** их license-file refs byte/hash verified в source
offer. MIT и Apache-2.0 — кандидаты для соответствующих идентифицированных copied
fragments в GPL3-контексте с сохранением их условий. Generator crate license
не присваивается generated output автоматически. Curated CXX-Qt MIT text содержит
placeholder copyright year/holders; он не заменяет точную file-level attribution.
Own bridge/application/build inputs доступны в source142 offer по конкретным SHA;
это не утверждение, что future final source совпадает с source142.

## Как attachment потребляет capture 9f51fae

[capture-consumption.json](capture-consumption.json) задаёт конкретный join:

1. Проверить manifest pins record/report/observed evidence, source/final profile
   и ELF binding. Не изменять статус или байты producer report.
2. Через `build-cxx-observed.json:input_origins[origin_path]` найти staged SDK path;
   по нему взять verified file из capture report. Сопоставить **origin + SHA**
   с `candidate-join.json:headers`, а не только Qt version/filename/package name.
3. Присоединить найденные notices, exact source fragment и SHA primary refs как
   reviewed candidates. `qconfig` становится final-version evidence только при
   его собственном точном hash match; один version query этого не доказывает.
4. Для `unbound_generated_sources` использовать retained text/hash и actual
   compile/depfile record. Generation provenance и output declaration проверяются
   отдельно. Данные final build могут закрыть этот metadata join после штатного
   retention; отдельная audit rebuild не нужна.

Unmatched final rows не получают лицензию из этого набора. Package142 остаётся
историческим, current SDK не становится final SDK до exact capture match.
