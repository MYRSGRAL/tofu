# L1: реализация для review

После одобрения root реализованы только preferences v2 и чистый planner.
Production startup/CLI/Qt/Main/backend dispatch не подключены.

`Store::open` мигрирует v1 в память, не пишет файл. Startup bool по умолчанию
false/false, target None. Неизвестный/повреждённый файл сохраняется, effective
settings OFF и запись заблокирована. Target содержит только typed metadata
source/profile/generations/snapshot/routing revision/engine/mode.

`save_startup(expected_revision, autostart_into_tray, autoconnect, target)`
возвращает новую Preferences и Durable/PublishedDurabilityUnknown. Повышение
startup revision проверяет overflow. Stale revision и изменённые original bytes
отклоняются. Старый `save` не может записать меньшую startup revision;
существующие изменения языка/probe/расписания сами её не повышают. Это уточняет
исходный проект: revision scoped к startup, а не глобальная ревизия Preferences.
API остаётся crate-private и пока не имеет production caller.

## Изоляция: точная граница

В `application.cpp:183–186` existing QLockFile сериализует normal GUI host
для canonical data-dir в одном runtime directory. Store сам не берёт lock.
Startup CAS корректен для сериализованного owner; два Store из разных процессов
не получают линейризуемого CAS от byte comparison/rename. Разные runtime dirs
и вне-GUI DesktopHost обходят этот Qt lock. Новая межпроцессная гарантия НЕ заявлена.

Bounded proposal root перед integration: либо ограничить startup writer этим
GUI owner (включая запрет второго runtime dir для того же data-dir), либо
выделить общий data-dir writer lock для ВСЕХ preferences writers и удерживать
его от read до publication/fsync. Не добавлять lock только в save_startup:
старый save иначе остаётся конкурентным writer. Lock policy, symlink/owner и
bounded acquisition должны пройти отдельный review. Внешний редактор без
соблюдения lock остаётся вне атомарной гарантии. L1 сохраняет byte fences,
но не подменяет ими lock authority.

## Planner не permit

`Planner` имеет один consumed latch на lifetime host; Stop закрывает latch.
Первое decide тоже закрывает latch, включая OFF и отказ. Вызывающий owner
должен дойти до startup barrier или его bounded deadline ДО decide; повторные
network/key/tray события не rearm. Новый host создаёт новый Planner.

Unknown/ephemeral/locked/unavailable custody, Unknown/Blocked/Recovery/foreign
active admission, stale generation, missing/invalid/mismatched binding дают
Noop/Blocked, никогда Connect. Local/System и engine участвуют в равенстве.
Ни команда, ни I/O, ни N5 proof не создаются. Eligible/Ready — только snapshots,
их нельзя передавать в исполнитель как permit.

До будущего dispatch отсутствуют: producer repository identity (особенно restore
и копирование БД), normal custody owner epoch, async cancellation/revalidation,
System policy/N5 admission и actual Connect. Bounded proposal root: producer
захватывает подтверждённый target в текущем repository owner, при restore/import
инвалидирует target и требует explicit confirm; dispatcher resolve через
SubscriptionService и сравнивает generations/revisions под текущим owner,
заново проходит реальные custody/admission gates после каждого await. До review
этого producer включать production автоподключение запрещено. Простое равенство
metadata двух разных БД не доказывает identity.
