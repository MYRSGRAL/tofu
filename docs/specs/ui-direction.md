# Направление переработки UI

Пользователь выбрал 2026-11-09 тёмный визуальный стиль
[highpriority.cloud](https://highpriority.cloud/) и простую компоновку присланного
скриншота: одна карточка выбранного сервера, крупная круглая кнопка подключения,
читаемый статус и вход в настройки через шестерёнку. Пользователь посмотрел
интерактивные варианты А/Б/В и выбрал **А — большая
кнопка по центру**. Эталон компоновки — вариант «Один фокус» в
[автономном макете](../../design/ui-variants.html). Карточка сервера расположена
над кнопкой; разделы «Подключение», «Серверы» и «Настройки» доступны через
постоянную нижнюю навигацию. Шестерёнка также открывает настройки.
Компоновка перенесена в нативный
Qt Quick-прототип и подключена к существующему Rust backend. HTML остаётся
отдельным макетом. Это не окончательное решение о toolkit.

## Цвет и типографика

Прочитанные stylesheet/inline CSS публичного сайта содержат токены:

| Роль | Значение из референса |
| --- | --- |
| Основной фон | `#070707` |
| Поверхность | `#191919` |
| Основной текст | `#f3f4f6` |
| Вторичный текст | `#9ba1ab` |
| Граница | `#29262e` |
| Лавандовый акцент | `#c3a6ef`, соседний оттенок `#c9b6ef` |

На сайте используются Unbounded для выразительных заголовков и Onest для текста.
Onest и Unbounded встроены в Qt resources вместе с OFL-лицензиями; установка
шрифтов в систему не нужна. Кириллица и масштаб 150–200% проверяются в собственном
окне Qt; полноценная приёмка живого Wayland остаётся отдельной. Не копировать Sota/logo
из скриншота или чужой бренд: приложение называется yonik.

Доминируют почти чёрный фон, спокойные поверхности, светлый текст и один
лавандовый акцент. Жёлтый акцент скриншота не заменяет выбранную палитру сайта.
Небольшие сигнальные цвета допустимы для ошибок/предупреждений, отдельно от бренда.

## Главный экран

- Выбранный сервер: название/страна, понятный переход к выбору, измеренная задержка
  только при наличии актуального результата. Не выдавать TCP-замер за скорость VPN.
- Одна основная кнопка connect/stop/cancel, крупная и узнаваемая, с ясным состоянием.
- Статус подключения и короткая причина ошибки/ограничения. `Limited` не рисуется
  успешным интернет-подключением по одному факту запуска ядра.
- Карточка сервера открывает раздел «Серверы». Элементов управления избранным
  в текущем GUI нет; библиотечное хранение избранного не является готовым UI.
  «Лучшие серверы» не выводятся как измеренный рейтинг без соответствующих данных.
- Шестерёнка открывает отдельный экран/раздел настроек.

Все настройки уходят в настройки: выбор ядра, адрес локального прокси, URL/статус HTTPS-проверки,
диагностические параметры. Подписки, обновление и выбор профиля находятся
в разделе «Серверы». TUN/DNS/Fake-IP/kill switch остаются будущими возможностями;
текущий GUI управляет только локальным SOCKS и не включает системный VPN.
Главный экран не превращается в набор настроек, таблиц и технических
панелей. Выбор сервера остаётся обычным пользовательским действием; управление
источниками подписки и их профилями объединено в разделе «Серверы».

На desktop сохранить простую иерархию скриншота с подходящими отступами и размерами,
не растягивать мобильный скриншот буквально на широкое окно. Проверить также
компактный размер окна и 125–200% scaling. Закрытие/трей/полный выход сохраняют
явный контракт lifecycle и kill switch, независимо от оформления кнопок окна.

## Настройки и поведение

Начальный размер — 420×760 логических пикселей, минимум 380×600. Палитра
highpriority.cloud: фон `#070707`, поверхности `#191919`, светлый лиловый акцент
и статические тёмно-фиолетовые градиенты. Короткие hover/press-переходы отключаются
через «Меньше анимации». Смена выбранного раздела отображается сразу.

Три постоянных раздела: «Подключение», «Серверы», «Настройки». В настройках
находятся подразделы «Подключение», «Диагностика», «Интерфейс» и «О приложении».
Создаётся только открытая панель; список серверов имеет собственную ограниченную
область без вложенной прокрутки. Раздел «Серверы» объединяет все подписки, поиск,
постраничный выбор профиля и управление выбранным источником: обновление, отмену
загрузки, переименование и удаление с подтверждением. Выбранный и активный
серверы различаются. Подробности показываются у кнопок
`?` при наведении или клавиатурном фокусе. Ручного выбора порта в GUI нет:
ОС выбирает loopback TCP/UDP-порт, пользователь копирует готовый адрес.

Для добавления подписки достаточно ссылки. Загрузка начинается сразу; JSON и
частичный импорт требуют просмотра отчёта. Необязательное имя и исключение для
локального HTTP-источника находятся в дополнительных параметрах. Состояния
загрузки/ошибки/review берутся из текущего backend snapshot, без отдельного
локального флага, который может устареть при объединении событий мостом.

Группировать подключение, подписки, сеть/маршрутизацию, защиту и диагностику.
Нереализованный режим не выдаётся за работающий переключатель. Включённая настройка
kill switch и подтверждённая applied-защита различаются явно. Подробные причины
и диагностика доступны по действию пользователя, а не занимают основной экран.

Нужны клавиатура, видимый focus, достаточные hit targets, читаемые состояния
ошибки/загрузки и уважение reduced motion. Не использовать постоянную пульсацию,
бесконечные декоративные анимации, размытие больших областей или idle polling.
Списки остаются виртуализированными и постраничными; 10 000 профилей не означают
10 000 визуальных объектов одновременно.

## Порядок

Первый рабочий А делается сейчас на существующем Qt Quick/CXX-Qt host. Сравнение
Qt Quick, GTK4 и Slint по [плану UI benchmark](../superpowers/plans/2026-11-09-linux-ui-benchmark.md)
проходит отдельно, когда пользователь сможет оставить сессию разблокированной.
Новый UI не ждёт ни этого замера, ни полного TUN/Fake-IP. Toolkit не выбирается по обещанному
расходу RAM: нужны измерения памяти, startup, отзывчивости, CPU/wakeups и скрытого
окна. После сопоставимых измерений подтвердить Qt либо перенести ту же выбранную
компоновку на другой toolkit, сохранив рабочий backend.

Поля DTO, доступность кнопок и команды нового экрана описаны в
[контракте UI/backend](ui-backend-contract.md). Он сохраняет различие выбранного
и активного сервера, ограничения локального SOCKS и семантику `Limited`.
