# tofu — прокси-клиент с открытым исходным кодом

Статус: проект документации для обсуждения, 8 ноября 2026 года.
Название проекта — **tofu**, написание строчными буквами. Пользователь подтвердил модель **open source**. В репозитории размещена [GNU GPL v3.0](../../LICENSE); дальнейшее уточнение варианта SPDX и условий зависимостей описано в [ADR-010 и O-09](decisions.md). Начальная реализация и выполненные проверки описаны в [README](../../README.ru.md) и [evidence](../validation/); продуктового приложения и измерений производительности пока нет.

Цель tofu — удобный нативный клиент с Xray-core и sing-box, TUN, Fake DNS, подписками и понятной маршрутизацией. Первая реализация предназначена для Linux. Общая логика изначально проектируется как переносимая Rust-библиотека, которую Android-приложение сможет использовать без копирования бизнес-логики.

Описание для репозитория: «Нативный прокси-клиент для Linux на Xray-core и sing-box: TUN, Fake DNS, маршрутизация по приложениям и работа в трее. В разработке».

Открытая поставка tofu должна включать собственные исходники, инструкции сборки, тесты и документацию. Лицензии и уведомления сторонних компонентов сохраняются отдельно; выбор лицензии tofu не меняет условия Xray-core, sing-box и GUI-зависимостей. Репозиторий tofu создан; релизов приложения пока нет.

## Основные положения

- Собственное ядро приложения — управление состоянием, профилями, правилами и настройками. Передачу пользовательского трафика выполняют Xray-core и sing-box.
- Рабочее предложение: одно выбранное прокси-ядро обслуживает основное подключение. Второе не запускается в фоне без задачи.
- На Linux существующий WireGuard/другой VPN нужен пользователю для приватных сетей. Эти маршруты и внутренний DNS сохраняются.
- На обычном Android два приложения с `VpnService` одновременно в одном профиле не работают. Для аналогичного доступа к приватным сетям предлагается будущая встроенная конфигурация WireGuard внутри выбранного ядра. Это отдельная функция Android, а не обещание совместимости с любым внешним VPN.
- В общей Rust-библиотеке отсутствуют зависимости от Qt, Android, D-Bus, systemd и управления интерфейсами ОС.
- UI обсуждается отдельно. Qt Quick/QML и Slint остаются кандидатами; ни один ещё не выбран пользователем.
- Работа через трей Linux и редактор маршрутизации по приложениям, процессам и адресам обязательны. Простой и расширенный режимы используют одну политику без потери правил при переключении.
- Проверки производительности включают длительную работу в трее и стоимость распознавания приложений; цели ресурсов подтверждаются относительно воспроизводимого baseline.
- Экономия ресурсов проверяется относительно работы выбранного прокси-ядра с тем же трафиком. «Нулевой расход батареи» не является технически подтверждённым обещанием.

## Что согласовано, а что предложено

Требования пользователя помечены в [реестре требований](requirements.md) как **обязательные**. Детали реализации, лимиты, дополнительные удобства и последовательность выпуска обозначены как **предложения**. Статус источника «подтверждено документацией» не означает, что интеграция уже проверена на машине или телефоне.

Первоначальная задача ограничивалась этим комплектом документов. По последующему разрешению пользователя начата реализация общих библиотек и изолированных engine-стендов. Требования и планы проверок в этом каталоге не являются отметками о прохождении gates; фактические результаты и ограничения сохраняются в [evidence](../validation/).
