# Контракт пакетных TCP-серий

Пакетный Linux API дополняет ручную серию из трёх TCP-проб. Это основа приёмки
10000 целей; кнопка массовой проверки в desktop пока не добавляется.

`check_tcp_batch` получает Vec<TcpBatchTarget>, параллелизм, timeout одной серии,
ограниченный mpsc Sender и Cancellation. Цель содержит уникальный opaque u64 ID
(включая ноль) и TcpProbeTarget без credentials. Результат возвращает тот же ID
и Result<TcpProbeSeriesResult, HostError>. Порядок завершения не равен входному.

Лимиты: до 10000 целей, параллелизм 1…32, timeout серии 0<t≤60 с, максимальная
ёмкость канала результатов 32. Некорректный пакет отклоняется до сетевого I/O.
Пустой корректный пакет допустим. Каждая серия выполняет свой DNS lookup один
раз и три соединения к выбранному полному адресу. Между разными целями нет
скрытого DNS/результатного кэша или дедупликации по credentials.

Scheduler держит только ограниченное число futures в существующем runtime.
Он не создаёт задачу на каждую цель и не запускает отдельный runtime. Сумма
активных и завершённых, но ещё не доставленных серий ограничена параллелизмом.
При полном выходном канале уже начатые серии продолжают polling: ожидание UI
не добавляется к TCP-времени и не задерживает обработку deadline. Ожидание
свободного места у потребителя отменяемо. Ошибка одной серии передаётся как её
результат; она не останавливает остальные цели. Отмена или закрытие получателя
останавливает пакет, уничтожая оставшиеся futures и сокеты. Drop внешнего
batch future также освобождает принадлежащие ему I/O без фонового продолжения.

Успешное завершение producer означает доставку всех результатов в канал, а не
их обработку UI: потребитель должен дочитать очередь. При отмене уже доставленные
элементы могут оставаться в канале. Controller обязан проверять собственные
source/profile revision и network generation, отбрасывая устаревшие результаты;
opaque ID и SocketAddr сами по себе не доказывают неизменность сети.

API не сохраняет историю и не объявляет частичные серии успешными медианами.
В журнал достаточно выводить ID/статус/счётчики; credentials и исходные URI
не нужны. Native DNS provenance, полный G-PROBE и энергопотребление приложения
остаются отдельными gates. Нагрузочная приёмка использует собственный pool
loopback listeners, не пользовательские подписки или публичные сервисы.
