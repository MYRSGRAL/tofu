# Доверенный реестр ядер для network helper

Компонент P12 готовит безопасный вход для последующих Prepare/Apply.
Он не авторизует клиента и не подтверждает применение сети. Пользовательский
`engine-dir` локального SOCKS-клиента остаётся отдельным непривилегированным путём.

## Источник доверия

Production API открывает фиксированный каталог `/usr/lib/yonik/engines`.
Адрес каталога, владелец, имя бинарника и ожидаемый SHA-256 не задаются клиентом
D-Bus. Каждый компонент пути открывается относительно directory FD с NOFOLLOW;
ожидается владелец UID0 и отсутствие group/world write. Реестр и бинарники
должны быть обычными файлами без дополнительных hardlinks и небезопасных прав.

Установка, изменение и удаление этого каталога принадлежат доверенному пакетному
механизму. Сетевой helper не скачивает ядра и не повышает доверие пользовательских
артефактов. Фиксированные имена исполняемых файлов — `xray` и `sing-box`.

## Формат registry.json

```json
{
  "schema": 1,
  "engines": [
    {"engine": "xray", "version": "26.10.31", "sha256": "<64 hex-символа>"},
    {"engine": "sing-box", "version": "1.14.4", "sha256": "<64 hex-символа>"}
  ]
}
```

Это схема, а не установочный manifest с действующими хешами. Допустима установка
одного из ядер; список содержит от одной до двух разных allowlisted записей.
Неизвестная schema/engine, повтор, лишнее поле, неверный SHA-256 и несовпадение
версии с `Engine::version()` отвергают manifest. В нём нет путей, argv,
environment, shell, systemd-unit или engine JSON. Размер manifest ограничен 4096 байтами.

## Неизменяемый исполняемый снимок

Конструктор проверяет manifest. Это не утверждение о работоспособности бинарника.
Выбранное ядро открывается через закреплённый directory FD и проверяется перед
созданием `BinarySnapshot`. В snapshot передаётся тот же уже открытый File;
строковый путь после проверки не открывается повторно.

SHA-256 и ELF-пределы проверяются при копировании в sealed memfd существующим
кодом snapshot. Один неизменяемый inode затем используется для version-check,
config-check и запуска. Подмена исходного имени после создания snapshot не меняет
исполняемый файл. Хеши/пути и сырые ошибки ОС не включаются в Debug/ошибки компонента.

Бинарник другого engine не копируется в memfd заранее. Проверенный manifest
не даёт права объявлять ещё не проверенный executable доступным. Дальнейший host
должен выполнить настоящий version/config-check; manifest не заменяет его.

## Интеграция

Prepare получает только типизированное намерение клиента, выбирает engine из
реестра, компилирует конфиг сам и связывает artifact с peer/session/generation.
Apply повторно проверяет авторизацию, окружение и неизменность artifact перед
эффектами. Сам реестр не создаёт permission token и не обходит G-DNS или проверку
TUN. Эти методы и реальная системная установка остаются отдельными частями P12.
