# yonik на Linux

[English](linux-en.md) · [Начало проекта](../../README.ru.md)

Инструкция для базы `db8226ef585b8251fe02ca3dbbe0f7ac759fc636`: Linux,
CachyOS/Arch x86_64, KDE Plasma/Wayland. Android отложен. Это развивающийся
клиент: рабочий пользовательский путь — локальный SOCKS5 для явно настроенных
приложений. Системный TUN, DNS/Fake-IP, kill switch и применение маршрутов
приложений через GUI пока недоступны (`system_tun=false`). Наличие helper в
пакете этого не меняет. Полная приёмка P25 не заявлена: лицензии, runtime
composition и требования производительности ещё открыты.

## Сборка и проверка происхождения

Используйте исходники официального [репозитория](https://github.com/MYRSGRAL/yonik),
проверьте выбранный commit и Cargo.lock. Команды ниже выполняются из корня
checkout. Нужны Rust >=1.85 (edition 2024), Qt6 Base/Declarative с Quick,
Controls, Widgets, Network, DBus и QML development tools, C++ toolchain,
SQLite и совместимый linker (lld/gold/mold). Для Wayland нужен Qt Wayland;
для хранилища — уже настроенный Secret Service рабочего стола.
Зависимости не устанавливаются приведёнными командами.

```sh
git rev-parse HEAD
python tools/install_desktop.py --help
```

На рабочей машине проекта тяжёлые Cargo-команды запускайте через штатный слот;
каталог создайте один раз, удерживайте lock его корня при каждом использовании:

```sh
yonik_build=/var/tmp/codex-myrs/transient/yonik-user-guide
mkdir -p "$yonik_build"
/home/myrs/projects/yonik/local/orchestration/with-rust-slot flock -s "$yonik_build" env CARGO_TARGET_DIR="$yonik_build/target" CARGO_BUILD_JOBS=1 cargo build --locked --release -p yonik-desktop --features gui
```

На другой машине orchestration wrapper проекта может отсутствовать: используйте
эквивалентный локальный контроль сборок, сохранив flock, внешний target и jobs=1.
До очистки перенесите бинарник в постоянный принадлежащий вам каталог, сохраните
SHA исходников, toolchain и SHA-256 бинарника. После завершения всех процессов,
использующих сборку, выполните под тем же lock `cargo clean` с тем же
`CARGO_TARGET_DIR`. Не удаляйте чужие временные каталоги.

Движки не входят в пакет и не скачиваются сборкой. Нужны официальные binaries
нужной платформы и **точно** ожидаемые байты; новая upstream-версия или локальная
адаптированная сборка не заменяет pin GUI:

| Путь внутри engine-dir | SHA-256 |
| --- | --- |
| `xray-26.10.31/xray` | `cc4b84d3069569f297a61f04b914f2bb37e9d202fd7b84cb50def1fc30fd40e1` |
| `sing-box-1.14.4/sing-box` | `1264361b5f8868c8768f7555d3e77e20118bf503c41ac08bb290a0d99056aa3a` |

Сверяйте происхождение и upstream checksums через официальный канал поставщика,
затем локальный SHA-256. GUI проверяет snapshot и config-check перед запуском;
несовпадение не обходите отключением проверок. Архив cleanbuild78 из исходников
eec7 — историческое evidence, а не доказательство latest binary.

## Запуск и пункт меню

Замените абсолютные пути своими постоянными путями:

```sh
/permanent/path/yonik-desktop --engine-dir /absolute/path/to/engines
python tools/install_desktop.py --binary /permanent/path/yonik-desktop --engine-dir /absolute/path/to/engines
```

Installer создаёт только пользовательский пункт меню и иконку, не копирует binary
или движки и не ставит системный helper. Не запускайте GUI от root.
Данные по умолчанию: `$XDG_DATA_HOME/tofu` или `~/.local/share/tofu`;
`--data-dir /absolute/private/path` выбирает другой каталог. Имя `tofu` и identity
Secret Service оставлены для совместимости зашифрованных данных. При недоступном,
заблокированном или утраченном ключе остановитесь и восстановите доступ к исходному
Secret Service: не удаляйте ключ/БД и не создавайте замену для существующей БД.
Plaintext fallback отсутствует. Ссылки подписок и credentials не передавайте в argv,
логи, screenshots и bug reports.

## Подписка, импорт и подключение

1. Откройте карточку сервера → **Серверы → Добавить**, вставьте URL подписки.
   Загрузка начинается после добавления. **Дополнительно → Локальный источник**
   разрешает HTTP/локальные адреса только для доверенного источника. **ID устройства**
   по умолчанию выключен: при включении отправляется случайный стабильный ID этой
   подписки, а не hardware ID. Ошибка лимита устройств не создаёт новый ID.
2. Проверьте accepted/rejected/flagged в **Проверке импорта**, страницы замечаний
   и предупреждение JSON. Подтверждайте только доверенный источник. **Сохранить
   профили** утверждает отчёт; **Отменить импорт** сохраняет предыдущий snapshot.
   JSON routes/DNS/inbounds исходника не становятся настройками вашей сети.
3. Выберите сервер, вернитесь на главный экран, нажмите центральную кнопку.
   Поддержка импорта протокола не гарантирует поддержку всех параметров ядром:
   несовместимость даёт ошибку, а не тихое ослабление TLS.
4. В **Настройки → Подключение** возьмите адрес SOCKS5. Настройте его явно в нужном
   приложении и проверьте его собственное поведение DNS. Порт обычно выбирается ОС;
   `--listen-port 10808` — диагностический override, а не обязательная настройка.
5. Для обновления выберите подписку в **Серверах** и запустите обновление. Там же
   отменяется текущая загрузка; **Ещё** позволяет переименовать/удалить подписку
   с подтверждением. Ошибка/отмена/отклонённый импорт сохраняет последний утверждённый
   snapshot. Удаление подписки удаляет её серверы с устройства.

GUI добавляет URL; отдельного выбора файла или ручного редактирования профиля нет.
Для проверки тела подписки (URI/Base64/поддерживаемый JSON) без активации есть CLI,
который читает stdin. Сохраните исходник приватно, вне git:

```sh
/home/myrs/projects/yonik/local/orchestration/with-rust-slot flock -s "$yonik_build" env CARGO_TARGET_DIR="$yonik_build/target" CARGO_BUILD_JOBS=1 cargo run --quiet --locked -p yonik-import < /private/path/subscription.txt
```

Это анализ, а не импорт в GUI: exit 0 означает полученный отчёт, включая ошибки
отдельных записей. Лимиты: 8 MiB входа, 32 MiB декодированного, 20 000 URI,
64 KiB на URI, JSON depth 64. См. [границы импорта](../validation/2026-11-09-subscription-import.md).
FR-06/07 целиком этими путями не закрываются.

GUI сейчас выбирает Direct для загрузки. API ManualProxy с доменным proxy endpoint
требует явно настроенного trusted DNS; GUI wiring этой настройки отсутствует.
Не считайте такой путь доступным и не заменяйте ошибку скрытым DIRECT.
Плановое обновление зависит от подтверждённых условий питания/сети/видимости;
unknown блокирует фоновый запуск (fail closed). Не рассчитывайте на обновление
в скрытом окне; при необходимости обновляйте вручную в открытом GUI.

## Состояние, настройки и выход

`Checking` ещё не успех. `Connected` подтверждает конкретный HTTPS endpoint через
текущий outbound в момент проверки; это не утверждение о глобальном интернете.
`Limited` оставляет ядро работающим без актуального HTTPS proof. После смены сети
переподключитесь вручную. TCP в **Диагностике** измеряет endpoint сервера, не
скорость VPN. Custom HTTPS URL и ожидаемый статус 200–299 задаются там же.
Не публикуйте URL с токеном. Поле очищается после отправки.

Ядро, порт, язык и безопасный URL сохраняются в preferences. URL с query,
credentials или fragment — session-only; после restart используется сохранённый
безопасный/default endpoint. Ошибку чтения/записи preferences не обходите удалением
файла: сохраните исходник и устраните права/доступность. Редактор маршрутизации
сохраняет только draft; **Применить к сети** выключено. Его правила не управляют
действующей SOCKS-сессией или приложениями.

Закрытие окна при доступном трее может скрыть его и оставить сессию. Для полного
завершения выберите **Выход / Quit** в трее и дождитесь остановки. Повторный запуск
с тем же data-dir открывает существующий экземпляр. `CleanupError` означает, что
очистка не подтверждена: повторите остановку, если доступна, и сохраните безопасное
описание ошибки. Не называйте это успешным отключением и не очищайте сеть вручную.

Изменение safeCopy в работе **#82 ещё pending**, не merged в рассматриваемую базу;
не обещается доступным в текущем main. Перед передачей диагностики самостоятельно
проверьте отсутствие секретов.

## Установка пакета, обновление, rollback и удаление

[Arch recipe](../../packaging/arch/README.md) закрепляет **e33fa190**, а не текущую
базу руководства. Он собирает GUI/helper/worker; runtime движков поставляется
отдельно. Для сборки следуйте recipe в disposable VM, без `makepkg -i/-s`,
проверьте архив до установки:

```sh
python tools/check_arch_package.py /absolute/path/yonik.pkg.tar.zst
```

Валидатор сверяет allowlist/права/metadata/ELF magic, не подлинность бинарника и
не его работоспособность. Неизвестный архив сначала проверяйте по происхождению.
Install/update/rollback матрица на чистой VM ещё не завершена; package path
нельзя считать принятым host installer. Для проверенного собственного пакета
обычные действия package manager в VM: `sudo pacman -U /absolute/path/yonik.pkg.tar.zst`,
удаление — `sudo pacman -R yonik`. Эти команды меняют систему; здесь они не выполнялись.
Нет hooks автозапуска, но явное обращение клиента может активировать D-Bus service.
Не запускайте helper вручную и не создавайте engine registry обходными командами.
Системный registry требует отдельного доверенного поставщика; пользовательский
engine-dir не даёт доверия helper. Не используйте `curl | sh`, широкие sudo
обходы, очистку nftables/routes или изменение keyring для обхода отказа.

Перед обновлением/удалением штатно остановите сессию и выполните Quit. Сохраните
предыдущий проверенный binary/package и приватную согласованную резервную копию
данных при закрытом приложении; ключ должен оставаться доступным в исходном
Secret Service. Для rollback пользовательского launcher восстановите прежний
binary и повторите установку пункта меню с его путём. Для пакета используйте
`pacman -U` с прежним проверенным архивом в VM. Совместимость старого binary с
новой schema БД не гарантируется: не открывайте единственную копию данных старой
версией; восстанавливайте согласованный backup отдельно, не заменяя ключ.

Для удаления пользовательского launcher удалите только созданные им
`applications/cloud.highpriority.yonik.local.desktop` и
`icons/hicolor/scalable/apps/cloud.highpriority.yonik.local.svg` внутри XDG data home,
после проверки владения/managed-маркера entry; чужие файлы оставьте. Отдельно
можно удалить собственный binary. Сохраняйте БД, пользовательские данные и ключи.
Удаление пакета не обещает очистить активную сеть: `/run`, чужие ресурсы и keyring
вручную не удаляйте. [Проверки руководства](../validation/2026-11-11-linux-user-guides.md).
