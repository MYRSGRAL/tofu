# G-DNS: требования к исполняемому адаптеру

Цель остаётся полной: FR-08/11/14/15/20/21 и D-01…D-07. Native names/ip-only
режимы не заменяют смешанную политику. Этот документ — рабочий план после проверки
возможностей, не утверждённая смена архитектуры и не разрешение на Go.

1. Закрепить воспроизводимые native-контроли: неполный A/AAAA; изменение адреса
   между route и dial; повторная выдача fake-IP внутри сессии/после restart.
   Использовать только отдельные user/net/PID/mount namespaces и синтетику.
2. Для полного пути нужна атомарная `ResolutionLease`: canonical name, полный
   A/AAAA/NODATA outcome, resolver path, реальные IP, TTL и network/engine/resolver
   epochs. Ошибка любого обязательного семейства не превращается в успех другого.
3. Route decision и фактический dial используют одну lease. Истечение TTL/смена
   epoch до dial требуют новой классификации всей политики, а не нового DNS при
   сохранении прежнего outbound. Ошибки не переходят к младшему allow/default.
4. Fake mapping должен иметь владельца engine-session, срок и ограниченный ledger.
   Нельзя отдавать новый домен по адресу ещё живого DNS lease другого домена.
   При исчерпании безопасного пула — явный отказ, а не скрытое переиспользование.
   Старые пулы/неизвестные mappings блокируются; restore/conversion реализуются явно.
5. Приватные зоны получают только свой resolver; неоднозначный private/public или
   два VPN блокируются до отправки потока. Управляющий Rust не становится TCP/UDP
   data-plane: поток остаётся в выбранном ядре/сети ОС.
6. Проверить adapter hooks обоих ядер, lifecycle, canonical mapping и ограничения
   process attribution; затем реализовать и повторить всю D-матрицу, не только новые
   контрпримеры. Digest/compatibility manifest должен описывать фактические бинарники.

В штатных проверенных конфигурациях нет доказанного пути для пунктов 2–4.
Кандидат — ограниченные native hooks плюс общий Rust resolver/ledger. Применение
Go-патчей требует отдельного явного ответа пользователя по его языковому ограничению.
Если Go остаётся запрещён, требуется другой подтверждённый адаптер; контракт DNS
не ослабляется автоматически ради возможности включить переключатель Fake DNS.

O-02 (поведение окончательного отказа TUN) также остаётся открытым. Его ожидание не
разрешает изменять системные routes/DNS/firewall. До принятого и проверенного плана
compiler сохраняет capability rejection смешанной DNS/Fake-IP политики.
