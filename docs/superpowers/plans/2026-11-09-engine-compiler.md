# Компиляция импортированного сервера

Основание: FR-03/04/06/08/10 и EngineHost из data-and-contracts.md.

1. Новый yonik-engine преобразует ParsedServer в конфигурацию Xray 26.10.31
   или sing-box 1.14.4. Вход остаётся типизированным; произвольный native JSON
   не исполняется. Версии — часть контракта, обновление требует проверки схемы.
2. Поддержать шесть импортируемых протоколов и совместимые TCP/WS/gRPC,
   XHTTP для Xray. TLS всегда с проверкой сертификата, REALITY — только
   поддерживаемое сочетание VLESS/TCP. Неизвестные, опасные, некорректные и
   неприменимые параметры дают статическую ошибку, а не теряются.
3. Создавать один SOCKS listener 127.0.0.1 с ненулевым портом и один proxy
   outbound; весь принятый трафик идёт через выбранный сервер. Нет TUN,
   системного DNS, маршрутов, direct fallback или запуска процессов из библиотеки.
4. Конфигурация содержит секреты: закрытый JSON, скрывающий Debug и явная
   запись в writer. CLI читает импорт из stdin, выбирает индекс сервера;
   обычный вывод — сводка, чувствительный JSON требует отдельного флага.
   Частичный импорт и native JSON нельзя активировать автоматически.
5. Сначала тесты отображения полей и отказов, затем реализация. Проверить
   настоящими pinned ядрами config-check и локальный SOCKS→proxy→echo путь
   в отдельном network namespace с отрицательной проверкой после остановки
   proxy server. Выполнить fmt/clippy/tests/MSRV/release/Android, обновить
   README RU/EN, независимый review и PR. Реальную подписку проверять в памяти.

Этот этап не закрывает полный EngineHost: управление жизненным циклом,
статистика, TUN, DNS, policy compiler, хранилище и GUI остаются отдельной работой.
