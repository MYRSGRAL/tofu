# Настраиваемая проверка HTTPS через выбранный сервер

Основание: FR-10, networking §7. Стандартный generate_204 требует ровно 204;
свой HTTPS endpoint получает явно заданный ожидаемый успешный статус 200…299.
Редирект не считается успехом. TLS, SOCKS5h и запрет env proxy сохраняются.

1. ProbeTarget хранит ожидаемый статус; LocalSession и его callers используют
   один predicate. Проверки включают неожиданный 200 при ожидаемом204,
   пользовательский200 и отказ конфигурации3xx/некорректногоURL.
2. GUI задаёт URL/статус только до Connect. Actor держит валидированный target,
   сессия получает immutable snapshot. DTO не содержит URL; настройка пока на
   сеанс. Поле URL скрыто по умолчанию и очищается после передачи.
3. GUI показывает вид результата: HTTP-код/длительность, TLS, timeout либо
   transport. Детальная атрибуция DNS/connect/tunnel пока не поддержана
   существующим reqwest adapter и не заявляется выполненной.
4. Положительный тест проходит через настоящий core и собственный VLESS/TLS
   fixture, с CA только в тестовом процессе. Оба ядра, mismatch-status и Stop/
   closed проверяются в собственном namespace без изменения сети хоста.
5. README RU/EN, независимое review точного head и исправления; PR/merge по
   ранее разрешённому процессу. FR-09 TCP и живой Wayland остаются открытыми.
