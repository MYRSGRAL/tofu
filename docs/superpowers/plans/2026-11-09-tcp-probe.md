# Ручная TCP-проверка выбранного сервера

Основание: FR-09 и networking §7. Одно ручное измерение с общим deadline пять
секунд: отдельно DNS, затем TCP connect; сокет сразу закрывается. QUIC/неизвестный
транспорт не получает ложный статус «сервер недоступен». Аутентификация и HTTPS
не проверяются, состояние активного proxy не меняется.

1. Сетевой адаптер Linux использует async UnixStream к systemd-resolved Varlink,
   без getaddrinfo worker threads или внешнего DNS fallback. Протокол: JSON/NUL,
   reply до 64 KiB, до 64 адресов, проверенный локальный peer, отмена закрывает сокеты.
   API: [systemd Resolve](https://github.com/systemd/systemd/blob/main/src/shared/varlink-io.systemd.Resolve.c).
2. IP literal пропускает DNS. Для двух семейств используются ограниченные
   параллельные попытки с чередованием IPv4/IPv6. Ошибки/timeout DNS и connect
   различаются; UDP-only получает «не применимо» до I/O.
3. Desktop actor запускает максимум одну TCP-задачу; отдельная priority Cancel
   отменяет только TCP и queued TCP requests. Stop/Shutdown отменяют также TCP.
   Source/profile/revision связывают callback с выбором; смена выбора очищает
   результат и отменяет устаревшую задачу. UI не получает credentials/raw URI.
4. GUI показывает endpoint, время проверки, DNS/TCP отдельно и явную границу
   результата. Нет фоновых повторов, скрытого ICMP или автоматического рейтинга.
5. Unit/integration: loopback connect и EOF, refused, fake resolver malformed/
   oversized/timeout/cancellation, границы адресов и stale selection. Qt smoke,
   fmt/clippy/tests/release/Android, README RU/EN, независимый review и PR.

История измерений и network-generation пока не реализованы; одиночный результат
не выдаётся за актуальный после смены сети. Полные G-UI/G-POWER и общая спека
остаются открытыми, как и живой Wayland при заблокированной сессии.
