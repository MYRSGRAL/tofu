# Реальные потоки через Linux TUN

Цель: продолжить G-LINUX воспроизводимой проверкой TCP/UDP IPv4/IPv6 без
внешней сети и без изменения сетевого состояния хоста.

1. Использовать закреплённые Xray 26.10.31 и sing-box 1.14.4 из предыдущего evidence.
2. В новом user/network namespace поднять четыре localhost echo-сервера:
   TCP/UDP на IPv4 и IPv6. Запустить одно ядро с TUN и синтетическим redirect
   назначения к соответствующему echo-серверу. Ни DNS, ни подписки не нужны.
3. Отправить непредсказуемую нагрузку к тестовым нелокальным IPv4/IPv6 адресам,
   маршрутизируемым только в TUN. Проверить маршрут, точный ответ и прирост
   RX/TX TUN. Повторить после перезапуска ядра.
4. После SIGTERM и SIGKILL проверить удаление TUN и невозможность повторного
   обращения к тестовому адресу, пока echo-серверы продолжают работать.
5. Запустить существующие проверки, обновить README/evidence и получить
   независимый review изменения. GitHub CI сейчас не стартует из-за billing
   lock аккаунта; этот внешний blocker не подменяется успешными локальными тестами.

Файлы: `tools/engine_traffic.py`, `tools/traffic_echo.py`,
`tests/engines/*-traffic.json`, `docs/validation/2026-11-09-tun-traffic.md`.
Общий lifecycle/изоляция переиспользуется из engine_smoke. Echo helper не
принимает пользовательских конфигов. Ошибка любой оси завершает suite ошибкой.
Сопоставление процессов, VPN/split DNS и энергетические проверки остаются
отдельными gates; успех перенаправленного echo не доказывает работу proxy outbound.
