# Три TCP-выборки одного endpoint

Основание: FR-09 и приёмка задержки в `docs/specs/validation-and-roadmap.md`.
UI Toolkit остаётся открытым до реальных замеров. Работа ниже не требует GUI
и не заменяет перенос А или полную приёмку DNS/Fake-IP.

1. Добавить `check_tcp_series` и `TcpProbeSeriesResult`, сохранив публичный
   одиночный `check_tcp`/его семантику. DNS выполнить один раз. Существующая гонка
   адресов выбирает победителя; первая выборка — длительность индивидуального
   успешного dial, без DNS/stagger/ожидания других адресов. Следующие две попытки
   идут последовательно к тому же полному SocketAddr (IP, порт, IPv6 scope).
2. Все стадии ограничены исходным timeout (в desktop 5 с), без продления на
   каждую выборку. Сокеты сразу закрываются без payload. Медиана — только три
   успеха; при первом сбое остановиться, сохранить частичные выборки/причину,
   median=None. NotApplicable/invalid timeout остаются явными. Не раскрывать
   endpoint через Debug. Подтвердить TDD, ограничение futures, drop, cancel,
   общую границу времени, одно разрешение DNS и адресную идентичность.
3. Перевести ручной desktop check на серию, сохранив существующие generation,
   profile/revision и network stamp guards. Не публиковать медиану отменённого
   или устаревшего результата. Добавить DTO count/samples и явную RU/EN подпись
   медианы в существующей диагностике; новая компоновка А пока не реализуется.
   Проверить три EOF без payload локальным fixture, выбор другого профиля,
   Stop/Shutdown/CancelTcp и существующую network-invalidation приёмку.
4. Документировать отличие от HTTPS/скорости VPN, частичные пробы и отсутствие
   DNS provenance/полного доказательства неизменности сети при неполном monitor.
   Проверки, независимый review, исправления, атомарные commits, PR и зелёный CI.
