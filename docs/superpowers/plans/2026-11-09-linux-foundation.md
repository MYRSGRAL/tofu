# Начальный этап реализации yonik

Цель: начать выполнение утверждённых спецификаций с проверяемой общей логики и диагностики среды. Работа разрешена пользователем; GUI и сетевые изменения пока не требуются.

Основание: docs/specs/architecture.md, networking.md, validation-and-roadmap.md.

## Порядок

- [x] Проверить доступность ядер, DNS-менеджера и Rust targets без изменения системы. Подписку исследовать только в памяти, выводить агрегаты без адресов и credentials.
- [x] Создать Rust workspace и yonik-domain без зависимостей ОС/GUI. Начальный срез policy: канонические IP-подсети, executable, порядок private VPN → LAN → пользователь → preset → default. Приватный маршрут без доступного VPN блокируется. Это не полный DNS/Fake-IP compiler.
- [x] Написать integration-тесты до реализации: IPv4/IPv6 и границы подсетей, AND/OR условий, неизвестный executable, порядок правил, исчезновение VPN, default. Выполнить test, fmt, clippy и release build.
- [x] Добавить README.ru.md, обновить README.md на английском. Явно указать ограничения и реальные проверки. Сохранить небольшие локальные коммиты.

Результаты: [evidence](../../validation/2026-11-09-foundation.md). Дополнительно созданы синтетические TUN lifecycle smoke fixtures и Rust CI на 1.85.1. Полные интеграционные gates остаются открытыми.

## Файлы и интерфейсы

Cargo.toml — workspace; crates/yonik-domain — переносимая модель политики и её чистый evaluator; tests/policy.rs — поведенческая приёмка. `Policy::evaluate(&Flow) -> Decision` не выполняет I/O; вход содержит наблюдаемый IP и необязательный проверенный executable. Полный DNS/IDNA и жизненный цикл реализуются отдельно после интеграционных gates.

## Ограничения

Не публиковать подписки и секреты. Не менять сеть хоста. Не выдавать evaluator за доказательство сетевого результата. Не запускать контейнеры и не делать push. CARGO_TARGET_DIR только в transient-каталоге с flock корня. Cargo.lock сохраняется как воспроизводимый lockfile; бинарные артефакты в Git не входят.

## Следующие gates

G-LINUX/G-DNS/G-APP требуют закреплённых Xray/sing-box, изолированного стенда, прав на TUN и реальных потоков. Проверка Android требует установленного target/NDK. Отсутствие этих prerequisites фиксируется, а не подменяется unit-тестами.
