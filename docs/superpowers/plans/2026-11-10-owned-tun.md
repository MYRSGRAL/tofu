# Управляемый TUN: план реализации

> Для исполнителей: выполнять по шагам с проверкой результата; независимые задачи делегировать с отдельным ownership.

Цель: helper владеет TUN и его ресурсами, оба закреплённых ядра используют этот
интерфейс, Stop/crash убирают сессионный захват с учётом kill switch.
Основание: P12/P13/P16, `docs/specs/platforms.md`,
`docs/superpowers/plans/2026-11-09-linux-network-helper.md`.

Ограничения: Rust 1.85.1, без нового unsafe/dependencies; TUN prefix `tofu` +
8 hex сохраняется. Никаких эффектов в host netns во время тестов. Нельзя считать
совпавшее имя или маршрут доказательством владения. Чужие ресурсы не удаляются.

- [x] Проверить оба настоящих engine с заранее созданным persistent TUN:
  ifindex/alias не меняются, TCP/UDP IPv4/IPv6 идут через TUN, TERM/KILL и cleanup.
  Ownership: `tools/owned_tun_smoke.py`; evidence в `local/validation/helper-owned-tun/`.
- [x] Добавить bounded IFLA_IFALIAS в read-only topology, сохранив неизвестные
  представления. Проверки malformed/duplicate/flagged и redacted Debug.
  Ownership: `network/topology.rs`, его tests и конструкторы LinuxLink.
- [x] По результату проверки ядер реализовать типизированный lifecycle TUN:
  exclusive create, journal intent до эффекта, полная метка владельца, отказ
  чужому/неоднозначному объекту, explicit cleanup; закрыть crash-окно create/alias
  либо оставить его неизвестным, не выдавая за успешное восстановление.
- [ ] Подключить адреса/routes/rules через отдельный bounded write transport:
  ACK от kernel плюс наблюдаемое состояние; без слепого retry после timeout.
  Проверить занятые IDs, неизвестные selectors, чужие изменения и частичный cleanup.
- [ ] Связать session PreparedPlan/registry worker с этим lifecycle, затем
  system-service/GUI; applied только после всех обязательных ресурсов.
- [ ] Пройти namespace traffic/crash-матрицу, независимое ревью и CI; обновить
  общий план/evidence без повышения процента до полного закрытия критериев.

Риски: persistent интерфейс может быть несовместим с режимом открытия engine;
route/rule не имеют уникальной kernel ownership-метки; alias не является защитой
от другого доверенного CAP_NET_ADMIN. Эти границы должны быть проверены и явно
описаны, а не скрыты успешным unit-тестом.

Промежуточный evidence: [owned TUN](../../validation/2026-11-10-owned-tun.md).
Ревью исправлений выполнено; общая session-матрица и CI кандидата ещё открыты.
